## 1. 扩面的两个目标

本阶段只验证向第二组件迁移、尝试第三种形态及处理规模增长的方法；不要求一次审计 `base/`、`foundation/` 全部生产代码。长期目标的主范围、依赖和各级分母见 [FULL-SCOPE-ROADMAP.md](FULL-SCOPE-ROADMAP.md)；本阶段的入口分母仅针对纳入的固定 scope，不外推为全范围覆盖率。

1. **迁移可行性**：同一双命题流程能否在第二个、门禁形状不同的组件上，从入口发现走到限定操作、主体、实际门禁、缺口或裁决，并由 `check` 复算。新增 IDL 数量或已给定变异体命中率不等于发现效果。
2. **真实效果**：只给 scope、固定知识/策略材料和预算时，能否提出有价值的疑点，压低契约差异误报，并清楚区分真实正例、限定排除、未定候选和覆盖不足。Builder-LLM 标签可作为显式来源的实验 oracle；与独立真值、真实漏洞召回分别报告，缺少分母就记为未评估。

扩面不是将 `roots` 列表放大后直接全量 live。入口数量、文件扫描和模型调用的增长来自不同环节，应分别测量和裁剪；不以牺牲源码校验、完整性或 `static-only` 结论边界换吞吐。

## 3. 分阶段执行

### E0. 清点与同机基准（不修改裁决器）

- 固定当前源码快照、两条现行规范、锚点、模型 ID 和版本，核对三条现存 canonical run 的 `check`。历史丢失 run 只作不可复核的背景记录。
- 在 Windows 原生环境测一次冷索引/冷 off、一次热索引/热 off，并分别统计：快照生成与解析、索引、入口发现、任务取证、静态证明、报告/check 的 wall time、CPU、峰值 RSS、读写字节、解析/保留行数、缓存命中、截断/歧义数；live 另记请求数、token、耗时与失败。已缓存的 pilot 运行只能算热路径；冷路径须在隔离的实验输出位置从头生成，不删除现有索引或 run。先保存原始测量及机器/Node 信息，不用单次总时长推断 P95。
- 从已存在的五根快照只读清点生产入口、绑定候选、构建变体与文档/策略来源；先选 **一个接口**，建议以 `os_account/IAccountIAM` 的 17 个 IDL 方法为候选进行绑定可行性调查。若无唯一实现或独立策略材料，换同根更合适的接口并记录原因，不硬套 sandbox_manager 的 owner 名或 `PolicyInfoManager` 操作。

产物：一个清点表和分阶段性能基准。清点表逐项列出 `entryKind/interface/method`、源文件、候选实现数、可疑操作种类、编译变体、门禁形状、知识/策略材料是否存在；所有计数注明分母与截断。

### E1. 第二组件的一条完整纵向路径

- 复制**数据配置**而非复制裁决代码：新 scope 固定 root、接口/owner 映射、入口类型、抽样规则及预算；发布该组件实际文档声明的 Builder 来源知识，另登记入口/对象预期策略的独立证据。文档差异只进入 `contractDeviation`，不得直接决定安全 `finding`。
- 从 `bin/autonomy.js`、`discovery.js`、`knowledge.js`、`tools.js` 和 `static-proof.js` 中识别 pilot 专用检查点；先让所选接口的绑定、操作候选与门禁识别成为可配置或组件局部 recipe。只有第二个真实使用者出现后才抽取共享接口。未知身份门、组合条件、间接调用及对象语义保持具名不足，不补一个“万能”正则。
- 首次只做 off：入口清点 -> 低成本绑定/操作定位 -> 对可裁决的入口取精确源码和构建条件 -> 双命题裁决 -> report -> `check`。每种新门禁形状至少一正一负测试；跨组件相同名称但不同 owner、目标歧义、源码哈希漂移、0/1 跳与截断都应给出实测结果。旧 pilot 回归必须不变。
- 选不同裁决路径的少量入口做受控 live -> 零远端 replay -> `check`，但**现有授权只覆盖 sandbox_manager-pilot**；新组件的外发范围和每 run 上限须另行明确授权。无授权时完成 off 与本地 mock/replay 测试，不把它们写成真实 live。

退出条件：至少一个第二组件的真实入口绑定到唯一实现与限定操作，取到完整且经哈希校验的源码，识别或明确限定实际门禁，形成可复算的 `excluded`、`candidate` 或门禁/策略层具名不足；单纯入口绑定失败不能算完整纵向路径。对每个入口公开绑定率、操作唯一率、门禁可判率和缺口分布。没有真实安全 finding 仍可以通过迁移可行性阶段，不能通过“真实正例能力”验收。

### E2. 由剖面驱动的非线性提取与处理

性能优化与消除无收益的防御性工程是扩面的正向工作，不必等单次任务超过旧的 5 s / 1 GB 门槛。现有 17 任务热 off 仍读约 483 MB、`check` 读约 746 MB，L1 重扫约 455 MB；先分别测事实扫描、源码窗口读/哈希、产物复算的真实成本，再按最主要成本投入，不一次重写所有层。旧 IAM/IAccount 规模下“不重构”的结论保持为历史实测，不约束新规模。

| 若测到的问题 | 最小改动路径 | 必须保持的性质 |
|---|---|---|
| 每次任务重复读/拆/哈希同一源码 | 单 run 内首次校验并缓存文件内容、行偏移和快照哈希；后续窗口复用，受控实验期间源文件变化则失效并停止使用旧证据。 | 最终证据仍指向固定源码，窗口截断如实登记；不在每个调用点重复读整文件。 |
| 每次进程重扫全局 JSONL 或内存逼近上限 | 优先让入口发现/绑定消费已建的按 root 索引，只读选中组件所需表；必要时再做分片或有界流式归并。 | 保留行数/ID 与截断对账，不静默丢坏行；Windows 原生运行。 |
| 同一调用点被多个入口重复证明 | 先在单 run 内按实际 callee/操作/主体/变体复用纯局部事实；仅确需跨 run 缓存时再加入版本、源码及知识/策略依赖指纹。 | 任务报告仍可单独复算，缓存不提高 assurance；无需为未采用的跨 run 缓存预建失效体系。 |
| 入口数使任务与模型预算线性膨胀 | 元数据清点与便宜的绑定/唯一操作筛选先行；按信号、歧义、新门禁家族和随机覆盖分层排队。对确定性 `excluded` 抽样复核，对高价值未闭合候选优先补证。 | 对所有入口保留覆盖状态和停止原因；不得只统计被模型挑中的任务，也不得让缺少模型调用自动变成排除。 |
| 每次迭代重复完整 `check`、哈希与全量测试 | 开发时先跑受影响入口的 off、定向测试和报告抽查；修改裁决/复算语义及阶段验收时跑完整 `check`、pilot 回归与全量测试。 | 阶段产物与 finding 仍可复算；不把未执行的验收标成通过。 |

`compile_commands.json` 已有分块扫描，勿再引入全文件 `JSON.parse`。本地单 run 缓存依赖固定输入，跨 run 复用才核验版本与必要传递依赖；不要预建签名、多层防篡改、复杂锁和恢复流程来防止假定的恶意攻击。构建变体不明时最多产出受限候选；不同变体不得混合成一条已证路径。

扩面到新接口/第三组件时重测同一语料旧/新冷与热路径，记录预处理成本、每入口总成本及完整复算频率；有重复成本和净收益时实施最小优化，即使单次尚未超过旧阈值。保留优化的依据是结论、缺口、截断和阶段 `check` 不漂移且总成本改善；没有净收益则不重构。总工作量随不同源文件增加仍会增长；目标是**避免重复扫描、无价值模型请求及过频的完整复算**，而非承诺总时长不随组件数增长。

### E3. 逐层扩大范围并测效果

- 第二组件先一个接口，再该组件其余相关接口，再第三个门禁/入口形态不同的组件。每次记录新增家族、绑定与不足分布，并复测读取、复算和请求成本；一旦重复工作随规模增加且最小改动有净收益，就实施 E2 对应优化，不等待固定门槛，也不把五根快照直接当作一次同质化产品跑。
- 抽样分层覆盖接口/入口类型、敏感操作、替代身份门、委托、歧义、无信号和内部函数。现有“每文件首函数”的样本只可作覆盖账本，不代表有安全发现召回；增加可重现的固定种子与层内分母。训练/调参样本与冻结评估样本按组件或缺陷家族分开，避免同一变异体改写落两边。
- 至少执行一组与调参样本分离的冻结跨组件**无种子发现**实验：只给 scope/知识/预算，不给目标方法或变异体标签；先冻结受控正例、合规例及歧义例的来源和分母，再盲跑并逐条复核提名及错误排除。分开公布给定变异体判定、无种子提名/召回、真实入口 finding 的策略与路径复核、覆盖率、耗时和成本。Builder 标签显式打标，非独立评测不称独立准确率；无真实正例时真实安全发现召回为 `null`，不能借受控桩填分母。无种子盲测失败也是效果结果，不得改标签或输入凑指标。
- 同模型 A/B/C/D 仅在需要判断检索或知识层增益、且对照能同任务同预算运行时补做；不阻塞真实审计成果。发现带来的调研价值和模型对照收益是两个不同问题。

## 4. 每轮交付与停止条件

**日常迭代**只记输入变化、处理的入口与缺口、一次 off 结果和相关测试；不重复复算不受影响的旧 run，不每次复制归档或生成四套报告。**阶段验收**再交四类可复核物：固定输入清单（源码/构建/知识/策略及必要哈希）、覆盖与性能表、裁决样例及失败/不足清单、代表性 off 与获批 live/replay 的 run ID 和完整 `check` 结果。旧 run 只读；真正需要复制归档时核对可读取性和一次哈希，不对每轮中间产物重复全量校验。

以下任一情况暂停扩大范围，先修本轮：事实或构建变体截断未计入分母；同一入口产生多实现却被当唯一；未经校验的源码、文档契约或模型意见被升级为安全 finding；阶段复算发现相同输入的非模型部分漂移；pilot 裁决回归；重复读、内存或请求成本随规模显著增长但尚无剖面。遇到新门禁家族时先留不足与样本，不把“未识别”改写成“无门禁”。单个研究态 off 中间 run 不要求全量归档验收。

**完成扩面验证**不是达到组件数量，而是在至少两个不同组件上展示可复算的完整路径、公开未覆盖量、测出主要成本并证明已实施的瓶颈优化对同一语料有净收益（无瓶颈则记录未实施理由），且完成上述冻结无种子实验及逐条结果核验。若真实正向策略锚点或独立真值仍缺失，将相应真实安全效果指标标为 `null`，继续称“跨组件迁移与负例纠偏有效”，不称“真实安全发现能力已验证”。

这一声明只适用于第一阶段，不得表述为 `base/`、`foundation/` 全部生产代码或 OH6.0 全系统已被审计；后续全范围基线按 [FULL-SCOPE-ROADMAP.md](FULL-SCOPE-ROADMAP.md) 单独推进和验收。

## 5. 目标模式的阶段验收与记录

新会话创建 `AG-EXECUTION/EXPANSION-RESULT.md` 作为实验账本，与本文的计划分离；首次写入注明日期、工作区状态和已存在的 run，不复制旧轮的成功叙述。每完成一阶段立即登记，不等到最后一次性打勾：

| 阶段 | 可核验的完成证据 | 未通过时下一步 |
|---|---|---|
| E0 | 固定输入清单、初始测试/`check` 输出、组件入口与绑定清点、冷/热测量口径及原始数据；说明历史缺失归档。 | 先解决快照漂移、截断或测量方法；仍可做只读接口调查。 |
| E1 | 第二组件真实入口的源码、绑定、操作、门禁、主体、规范/策略材料、具名不足或裁决的逐项引用；off run 与 `check`，pilot 回归；获授权才补真实 live/replay。 | 没有唯一操作时缩小接口或切换候选，不能以未绑定 observation 充数。 |
| E2 | 随新接口/组件增长复测 L1 扫描、源码窗口、复算与请求成本；若优化，旧/新同输入冷/热成本、语义哈希、缺口及必要失效测试；记录删去的重复校验步骤和节约量。 | 结论漂移、截断或净成本变差则不保留新优化；单次低于旧门槛并非拒绝消除重复工作的理由。 |
| E3 | 冻结盲测样本与来源、完整入口分母、未分析原因、实际执行的无种子发现、与已给定样本判定分开统计、真实案例逐条核验；最后同步规范的已实现/未实现状态。 | 缺少真实正例/独立真值时相应指标为 `null`，仍须交付盲测实测结果，不制造样本结论。 |

日常记录只保留能继续实验的输入变化、关键分母、run ID、失败与下一动作；阶段验收汇总 `snapshotId`、scope/版本/知识/锚点指纹、实际模型/模式、任务/工具/请求分母、耗时/峰值内存、`check` 结果、报告哈希及性能前后对照。不为防恶意操纵 Agent 增设额外日志、签名或防篡改账本。预算耗尽、模型不可用、缺少新范围外发授权时，只停止依赖该资源的子步骤；其它 off、定向测试和清点继续。完成依据仍是上表的真实产物，而非文档或测试数；最终分别陈述迁移可行性、性能收益和真实安全效果。
