# OpenHarmony 6.0 base/foundation 生产代码审计总目标

> 状态：总目标、阶段时间表与验收口径，不是已实现能力或逐项编码方案。裁决和证据等级以 [AGENT-ARCHITECTURE-GUIDE.md](AGENT-ARCHITECTURE-GUIDE.md) 为准；[EXPANSION-PLAN.md](EXPANSION-PLAN.md) 是已执行的第一阶段跨组件迁移指南，不改变静态 finding 的门槛。
>
> 研究态前提：Agent 只用于本地实验，不把恶意攻击 Agent、产物篡改或多租户隔离当作扩面目标。性能优化和去除无收益的防御性工程与覆盖扩展同等重要；保留防止事实失真、模型误判和覆盖漏计所需的最小证据，以及实际外发请求的授权边界。

## 1. 审计对象

目标是对固定 OpenHarmony 6.0 源码版本中 `OpenHarmony/base/` 与 `OpenHarmony/foundation/` 下**全部生产代码**建立可对账的静态审计范围，并纳入完成这些审计所需的跨目录依赖。称为“base/foundation 全范围生产代码静态审计”，而不是“OH6.0 全系统代码审计”：`kernel/`、`drivers/`、`applications/`、`device/`、`vendor/` 等目录不是无条件主审计范围，但其必要依赖仍须纳入。

- **主范围**：两棵目录下所有组件的生产实现、接口和头文件，以及决定生产行为的构建规则、注册元数据和配置。当前产品未启用但属于该版本生产代码的条件分支和特性同样在清单内；注明适用变体，不因未进入单个产品的编译数据库而消失。源码语言、入口和操作类型以实际代码为准，不受当前 C/C++、IDL、SA 词表限制。
- **必要依赖**：从构建、接口、调用、注册/消息和运行时交互追到主范围外的源与事实，包括权限定义、身份服务、实际调用方、对象归属、生成器输入和第三方实现。决定安全边界或承载待分析路径的依赖须做相应代码审计；仅解释语义的依赖须固定来源并取证。与主范围无关的外部代码不自动纳入全量审计。
- **非生产材料**：测试、mock、fuzz、示例、基准和文档可作证据，通常不计入生产代码分母；以实际构建/发布角色而非路径名判断。生成的生产源码按来源和变体记账，不将输入与输出静默重复计数。
- **配置宇宙**：固定源码版本和可识别的发布产品/系统类型、特性开关、宏及生成规则；逐项登记构建适用性。构建条件或动态目标无法确认时标未知，不用单一产品配置代替全范围。

## 2. 覆盖与结果口径

| 层次 | 可声称的完成内容 | 不能推导 |
|---|---|---|
| 范围清点 | 主范围与必要依赖有来源、角色、版本、纳入或排除理由。 | 已分析所有行为。 |
| 事实及入口覆盖 | 各语言/变体的抽取、入口绑定、截断、歧义与失败有分母和原因。 | 入口已获安全裁决。 |
| 有效静态审计 | 限定主体、对象、路径、操作的证据与裁决可复算；不足及未分析量公开。 | 存在缺口的代码被证明安全。 |
| 效果验证 | 给定样本、无种子发现和真实案例分开报告来源、误报、漏报、未知分母。 | Builder 自标、测试通过或零 finding 证明无漏洞。 |

覆盖账本至少按**组件、生产文件、函数、入口、敏感操作、构建变体**公布总数与状态；入口区分 `已裁决 / candidate / 证据不足 / 未分析 / 不适用`，标出未发现入口、未绑定、未知语言、构建不明、解析失败、预算停止等原因。依赖单列，不与主范围重复计数；不同层次的覆盖率不能混用。

“全范围已清点”要求主范围及必要依赖无静默遗漏；“全范围完成有效静态审计”还要求生产入口与安全相关路径均有审计状态、未分析量为零，并披露证据不足和剩余盲区。即便达到工程覆盖目标，也只对证据闭合的限定命题给 `static-only` finding 或 scoped excluded，不能宣称整个系统安全或发现全部漏洞。真实正向 finding 须有说明入口、对象、主体与操作预期约束的策略锚点；文档差异只是线索和契约比较。

每个新批次的具体实现、预算与入口选择由上一批的实测结果决定；本路线图不预设全仓一次运行或万能解析器。常规工具调用使用 Windows 原生环境；Linux/WSL 仅作为逐次批准的例外。live 外发仅限已有明确授权的 scope 和预算，不由本时间表自动扩权。

**贯穿各阶段的性能口径：** 开发迭代只处理改变的组件/入口，跑定向 off 与测试；阶段验收再检查代表性旧 run、完整回归、语义一致性和报告复算。先测事实表重扫、整文件窗口读取/哈希、模型请求与完整 `check` 各占多少，再消除最大重复项；单次尚未超过任意耗时/内存阈值也可优化随组件数增长的固定读放大。缓存只需覆盖实际复用边界：单 run 复用已核验源码，确需跨 run 复用才处理变更失效。不为假设的攻击增加防篡改签名、冗余哈希链、多层锁或额外隔离。覆盖分母、源码与构建来源、具名不足以及最终可复算结论不能为提速而省略。
